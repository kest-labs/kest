# Quickstart

## Kest CLI in 60 seconds

Kest is the API verification layer for AI coding agents. Run these in your API
repository while your server is running (replace the base URL with yours):

```bash
curl -fsSL https://kest.dev/install.sh | bash
kest init --base-url http://localhost:8080   # .kest/ workspace + sample flow
kest get / -a "status < 500"                 # first request, recorded to history
kest run .kest/flow/smoke.flow.md            # run the sample flow
claude mcp add kest -- kest mcp              # let Claude Code verify its changes
```

When a step fails, `kest run` prints the record ID; inspect it with
`kest show <id>`, re-send it with `kest replay <id>`, or get an AI diagnosis
with `kest why <id>` (needs `kest config set ai_key <key>`).

> `kest mcp` and `--json` are newer than the latest release (v0.7.7). Until the
> next release, build from source:
> `git clone https://github.com/kest-labs/kest.git && cd kest/cli && go build -o ~/.local/bin/kest .`

See [Kest CLI](/en/documentation/kest-cli) for the full command reference.

## Platform API

The rest of this page covers the Kest platform (Web Console) API.

## Base URLs

Use these base URLs when working against the Kest platform API:

```bash
Production: https://api.kest.dev/v1
Local:      http://localhost:8025/v1
```

For health probes exposed at the root level, see the `API Reference` entries for `/health`, `/health/live`, and `/health/ready`.

## 1. Create an account

Use `POST /register` to create a user.

```bash
curl -X POST "http://localhost:8025/v1/register" \
  -H "Content-Type: application/json" \
  -d '{
    "username": "demo",
    "email": "demo@example.com",
    "password": "secret123"
  }'
```

## 2. Log in

Use `POST /login` to get a bearer token.

```bash
curl -X POST "http://localhost:8025/v1/login" \
  -H "Content-Type: application/json" \
  -d '{
    "username": "demo",
    "password": "secret123"
  }'
```

## 3. Create a workspace

```bash
curl -X POST "http://localhost:8025/v1/workspaces" \
  -H "Authorization: Bearer <jwt>" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Demo Workspace",
    "slug": "demoworkspace",
    "type": "team",
    "visibility": "private"
  }'
```

## 4. Generate a CLI token

Generate a workspace-scoped token for syncing local specs.

```bash
curl -X POST "http://localhost:8025/v1/workspaces/<workspace-id>/cli-tokens" \
  -H "Authorization: Bearer <jwt>" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "local-dev",
    "scopes": ["collection:read", "collection:run"]
  }'
```

## 5. Upload specs from the CLI

```bash
curl -X POST "http://localhost:8025/v1/workspaces/<workspace-id>/cli/spec-sync" \
  -H "Authorization: Bearer <workspace-cli-token>" \
  -H "Content-Type: application/json" \
  -d '{
    "source": "kest-cli",
    "specs": [
      {
        "method": "GET",
        "path": "/users",
        "title": "List users",
        "version": "1.0.0"
      }
    ]
  }'
```

For detailed field definitions and examples, use the corresponding `API Reference` pages.
